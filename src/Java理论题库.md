3. static关键字的作用
   ```
   static主要有4种使用情况：成员变量、成员方法、初始化块和内部类

   ```

6. 什么是方法的重写(Override)？
   ```
   当子类需要修改父类的一些方法进行扩展,增大功能,程序设计者常常把这样的一种操作方法称为重写
   1.子类重写的方法的方法名和形参列表与父类中的方法名和形参列表相同
   2.子类重写的方法的访问权限修饰符不小于父类中的方法的访问权限修饰符
   3.返回值类型：
       3.1父类被重写的方法的返回值类型是void，则子类重写的方法的返回值类型只能是void
       3.2 父类被重写的方法的返回值类型是A类型，则子类重写的方法的返回值类型是A类或A类的子类
       3.3 父类被重写的方法的返回值类型是基本数据类型，则子类重写的方法的返回值类型必须是相同的基本数据类型
   ```

9. String、StringBuilder、StringBuffer区别
   ```
   String是不可变的。一旦创建了 String 对象，其内容就无法更改
   要是对 String 进行拼接等修改操作，实际上会生成一个新的 String 对象。
   StringBuilder 和 StringBuffer是可变的。在对这两个类的对象进行修改时，不会创建新的对象
   String是不可变的，所以它是线程安全的。多个线程同时操作同一个 String 对象也不会出现问题。
   StringBuffer是线程安全的，每个方法都加了同步锁
   ```

10. 抽象类和接口各自特点？
   ```
   抽象类不能被实例化，抽象类可以有抽象方法，也可以没有抽象方法，一个类只能继承一个抽象类
   接口不能被实例化，接口没有构造器，接口没有初始化块，
   接口里所有的变量都是公开的静态常量，接口里有抽象方法、默认方法和静态方法，
   接口里所有的方法都是公开的，一个类可以实现多个接口，一个接口可以继承多个接口
   抽象类用于表示 "is-a" 的继承关系，接口用于表示 "has-a" 的能力扩展，
   ```
   
11. int和Integer区别
   ```
   1. 本质区别
      int：基本数据类型，直接存数值，不属于对象
      Integer：int的包装类，是对象
   2. 默认值不同
      int 默认值：0
      Integer 默认值：null
   3. 如何比较数值
      int用==直接比较数值；
      Integer如果用==比较数值，则分为两种情况:
      （1）-128 ~ 127 之间：会缓存，== 结果为 true
      （2）其他数值则结果为false，因为会创建新的Integer对象
      因此Integer必须用equals()比较是否相等
   ```

12. 浅复制和深复制的区别
   ```
   浅复制
      只复制对象本身及基本数据类型成员
      对于引用类型成员，只复制引用地址，不复制引用指向的对象
   深复制
      不仅复制对象本身及基本数据类型成员
      还会递归复制所有引用类型成员所指向的对象
   在java中，Object.clone()方法是浅复制，如果需要深复制，必须手动处理所有引用类型成员的复制
   ```

13. ArrayList和LinkedList区别
   ```
   ArrayList是Array(动态数组)的数据结构，LinkedList是Link(链表)的数据结构。
   当随机访问List（get和set操作）时，ArrayList比LinkedList的效率更高，因为LinkedList是线性的数据存储方式，所以需要移动指针从前往后依次查找。
   当对数据进行增加和删除的操作(add和remove操作)时，LinkedList比ArrayList的效率更高，因为ArrayList是数组，所以在其中进行增删操作时，会对操作点之后所有数据的索引造成影响，需要进行数据的移动。
   ```

14. List和Set区别
   ```
   List是有序的集合，可以存储重复的元素，可以根据索引访问元素；
   而Set是无序的集合，不允许存储重复的元素，不能根据索引访问元素。
   List通常用于存储需要按照顺序访问的元素；而Set通常用于去重和判重操作。
   ```

17. ArrayList实现原理?
   ```
   1. ArrayList 底层就是一个 动态扩容的Object[]数组
   2. ArrayList初始默认容量为10
   3. 当数组容量不够用时，会复制一个新数组进行扩容，新容量 = 旧容量 × 1.5
   4. 频繁扩容会影响性能，所以大数据量建议预设容量
   ```

18. 写出HashMap(散列表)的实现原理

   ```
   1.基于桶(数组)+[链表|红黑树]
   2.将一个元素放入的过程?
    基于key生成一个hashcode，然后对桶的数量求余，得到一个索引值，根据该索引找到桶；
    如果桶里没有元素，那么就将元素直接放入；
    反之，如果桶里已经有元素了，就会使用尾插法将元素插入到当前单链表的尾部；
    如果桶里的元素达到8个时候且数组长度≥64时，为了提高查询速度，会将该单链表升级为红黑树；
    反之，如果桶里的元素减少到6个的时候，为了减少维护成本，于是会将红黑树退化成单链表
   3.查询一个key的过程?
    （基于key生成一个hashcode，然后对桶的数量求余，得到一个索引值，根据该索引找到桶；
     如果桶里没有元素，那么就返回null；
     如果有元素呢，会基于单链表或者红黑树来查询，结合equals方法）
   4.负载因子(默认值0.75)
     当map里元素的个数达到桶的个数*负载因子的时候，就会进行扩容，也就是当前的桶的个数*2；
     假设当前16个桶，那么当元素达到12个时候，桶的个数会变成16*2=32个；
   5.初始桶的个数是16个
   ```

22. 如何处理不安全的线程(并发安全)

   ```
   加锁
   加锁的本质是让程序在执行时不再同时而是顺序执行，就是不允许在一个线程还没有执行完的时候另一个线程插进来执行。
   锁又分为悲观锁和乐观锁。
   悲观锁是假定一定会有其他线程来抢。乐观锁是假定没有其他线程来抢，只是最后根据数据有没有被改变来判断是否已经被抢。
   (1) synchronized
   synchronized就是java提供的悲观锁机制，悲观锁是一种重量级锁，对性能有很大影响。
   (2) 显式锁Lock
   synchronized无需手动释放锁，只要包围的代码块执行完成即释放锁。还有另一种显式加锁、手动释放的锁机制，
   比如可重入锁ReentrantLock,也属于悲观锁。
   (3) Atomic(乐观锁)
   对基本数据类型，java提供了atomic包，其中提供了很多类，如AtomicInteger、LongAdder等。
   (4) 并发容器类
   java还提供了一些并发容器，ConcurrentHashMap、CopyOnWriteArrayList、BlockingQueue等。
   
   ```

26. 数据库内连接和外连接区别

   ```
   内连接是一种返回两个表中满足连接条件的行的连接方式。它只返回在两个表中都存在匹配行的数据
   外连接会返回一个表中的所有行，以及另一个表中满足连接条件的行。如果在另一个表中没有匹配的行，结果中会使用 NULL 填充相应的列。
   外连接可以分为左外连接、右外连接和全外连接（mysql暂不支持全外）
   ```

27. 数据库设计的范式和反范式是什么？

   ```
   第一范式:数据库表的每一列都是不可分割的基本数据项
   第二范式:一张表在满足第一范式的基础上，没有包含在主键中的列完全依赖于主键，而不只依赖于主键的一部分
   第三范式:一张表满足第二范式的要求，并且不存在任何字段传递依赖于主键
   反范式:在数据库设计中，有意地冗余部分数据以提高查询性能的一种技术。这是一种与范式相反的设计方法。比如将多个表合并为一个大表，以减少JOIN操作。
   ```


28. 数据库事务四大特性（ACID）?
   ```
   1. 原子性
      事务是一个不可分割的操作单元，要么全部执行成功，要么全部失败回滚
   2. 一致性
      事务执行后，数据库必须从一个一致状态转变为另一个一致状态，满足预定义的规则
   3. 隔离性
      并发事务的执行互不干扰，每个事务感觉不到其他事务同时在执行
   4. 持久性
      事务一旦提交，其对数据库的修改就是永久性的，即使系统故障也不丢失
   ```

31. 什么是复合索引，什么是最左匹配原则
   
   ```
   复合索引也叫联合索引，是一种在数据库表上创建的索引类型，它由多个列组合而成。通过使用复合索引，可以显著提高涉及多个列的查询的性能。
   这个原则的核心在于索引的使用方式,特别是当涉及到多个字段的联合索引时,
   如果查询条件能够从联合索引的最左边开始匹配,并且没有遇到范围查询如（>、<、between、like等),那么整个查询就可以充分利用联合索引的效率。但是，一旦遇到范围查询，匹配过程就会停止，并且范围查询之后的字段将无法使用索引。
   ```

33. 数据库索引B树和B+树区别？

   ```
   B+树特点:
   1. 非叶子节点只存储键值信息。
   2. 所有叶子节点之间都有一个链指针。
   3. 数据记录都存放在叶子节点中。
   B+树优点:
   1.由于B+树在非叶子结点上不包含真正的数据，只当做索引使用，因此在内存相同的情况下，能够存放更多的key
   2.B+树的叶子结点都是相连的，因此对整棵树的遍历只需要一次线性遍历叶子结点即可，所以便于区间查找和搜索
   ```

41. mybatis中的sql，使用#和$区别

    ```
    1. MyBatis处理#占位符，使用的JDBC对象是PreparedStatement 对象，执行sql语句的效率更高，能够避免sql注入，使得sql语句的执行更加安全
    2. MyBatis处理$占位符，使用的JDBC对象是Statement 对象，执行sql语句的效率相对于#占位符要更低，sql语句使用的是字符串连接的方式，有sql注入的风险，存在代码安全的问题。
    ```

43. spring中事务失效场景
    ```
    1.方法访问权限问题
      @Transactional只能用于public方法，对private或protected方法无效
    2.自调用问题（同类方法调用）
      同一个 Bean 内的非事务方法调用事务方法，事务失效（因为 AOP 代理未生效）。
      可通过注入一个本类对象来解决。
    3.异常被捕获且未抛出 
      事务回滚的默认触发条件是 抛出未捕获的 RuntimeException 或 Error。
      如果方法内捕获了异常（如 try-catch）且未重新抛出，事务会认为执行成功，不会回滚
    4. 异常类型不匹配
      @Transactional 默认只对 RuntimeException 和 Error 回滚。
      如果抛出的是受检异常（如 IOException、SQLException），且未通过 rollbackFor 指定，事务不会回滚
    ```

44. 什么是IoC和AOP，作用分别是什么？

    ```
    IoC（Inversion of Control，控制反转）是一种软件设计原则，传统的程序设计中，对象之间的依赖关系由对象自己管理和创建。而在IoC中，这种依赖关系的控制权被反转了，由容器来负责管理对象的创建和依赖注入。
    IoC可以降低代码的耦合度。对象之间的依赖关系由容器来管理，对象本身不需要关心具体的实现。这样，当需要替换某个对象时，只需要调整容器的配置，而不需要修改依赖该对象的其他代码
    AOP全称Aspect Oriented Programming，即面向切面编程，通过将横切关注点（如事务、安全性和缓存）从程序代码中分离出来，并在程序运行时动态地将它们与程序代码进行组合
    Spring AOP基于动态代理实现
    ```

48. JDK动态代理和CGLIB动态代理区别

    | 对比维度   | JDK 动态代理                       | CGLIB 代理                            |
            | ---------- | ---------------------------------- | ------------------------------------- |
    | 底层原理   | 基于接口实现（代理类实现目标接口） | 基于继承实现（代理类继承目标类）      |
    | 目标类要求 | 必须实现至少一个接口               | 可以不实现接口，但不能是 `final` 类   |
    | 效率       | 初始化快，接口方法调用效率高       | 初始化稍慢，方法调用效率接近 JDK 代理 |

		Spring AOP 默认根据目标类是否实现接口选择代理方式：
	    若目标类实现了接口则优先使用JDK动态代理，否则使用CGLIB代理。

54. Redis数据淘汰策略
    ```
        redis提供8种数据淘汰策略：
        •	volatile-lru(最常使用)：从设置了过期时间的键值对中，挑选最近最少使用键进行淘汰，优先保留最近使用过的键。
        •	volatile-lfu：从已设置过期的Keys中，删除一段时间内使用次数最少使用的
        •	volatile-ttl：在设置了过期时间的键值对中，优先淘汰剩余过期时间最短的键
        •	volatile-random：从设置了过期时间的键值对中，随机选择键进行淘汰
        •	allkeys-lru(最常使用)：从所有的键值对中，选择最近最少使用的键进行淘汰，无论键是否设置了过期时间
        •	allkeys-lfu：从所有Keys中，删除一段时间内使用次数最少使用的
        •	allkeys-random：从所有的键值对中，随机选择键进行淘汰，不区分键是否设置了过期时间
        •	no-enviction（默认）：禁止驱逐数据(不采用任何淘汰策略)
    ```

55. Redis持久化策略

     ``` 
     1.RDB(快照持久化)
         RDB 持久化是将 Redis 在某个时间点上的数据快照保存到磁盘的二进制文件中。
             优点：快照文件体积小，加载速度快
             缺点：数据安全性低,若触发快照后宕机，期间修改的数据会丢失
     2.AOF(追加日志持久化)
         AOF 持久化是将 Redis 执行的所有写命令追加到一个文件中，在 Redis 重启时，通过重新执行这些命令来恢复数据。
             优点： 数据安全性高,可配置每秒实时刷盘，丢失数据少；
             缺点： AOF文件体积远大于 RDB，加载恢复速度慢；
     3.混合持久化(官方推荐) 
          生产环境首选，兼具RDB加载快、AOF数据安全的优点
       
     ```

56. 缓存穿透、缓存雪崩和缓存击穿以及解决方案是什么？

    ```
    缓存穿透是指查询一个一定不存在的数据，由于缓存是不命中时需要从数据库查询，查不到数据则不写入缓存，这将导致这个不存在的数据每次请求都要到数据库去查询，造成缓存穿透
    解决办法：
    1. 缓存空值
    即使数据库查不到数据，也把 `null` 或特殊标记存入缓存，并设置较短的过期时间（如5分钟，后续相同请求直接从缓存返回，避免打到数据库
    2. 布隆过滤器
    将所有可能存在的数据哈希到一个足够大的bitmap中，一个一定不存在的数据会被这个bitmap拦截掉，从而避免了对底层存储系统的查询压力。

    缓存雪崩是指缓存大量失效的时候，引发大量查询数据库。
    解决办法:
    1. 设置不同的过期时间
    给缓存的过期时间加上随机值(如基础时间 + 随机几分钟)
    2. 限流与降级
    使用 Sentinel 、Resilience4j等限流组件，在数据库压力大时自动降级

    缓存击穿是指 某个热点 key 在过期的瞬间，大量并发请求同时到达，由于缓存失效，这些请求全部打到数据库，造成瞬时压力剧增
    解决办法：
    1.使用锁，单机用synchronized,lock等，分布式用分布式锁。
    2.缓存过期时间不设置，而是设置在key对应的value里。如果检测到存的时间超过过期时间则异步更新缓存
    ```

57. 如何保证缓存和数据库数据的一致性

    ```
    更新缓存和数据库有四种方案：
    - 先更新缓存，再更新数据库
    - 先更新数据库，再更新缓存
    上面这两种方案因为更新缓存效率较低，所有不考虑
    - 先删除缓存，后更新数据库
    如果出现这样情况： 1、线程A删除缓存中的数据 2、线程A更新数据库，尚未更新完成 3、线程B查询缓存中的数据，未命中  4、线程B查询数据库旧数据 5、线程B将旧数据同步到缓存 6、线程A更新数据库成功，从而产生数据库新数据和缓存旧数据不一致的情况
    可采取延迟双删:
    （1）先淘汰缓存
    （2）再写数据库
    （3）休眠 1 秒，再次淘汰缓存 这么做，可以将 1 秒内所造成的缓存脏数据，再次删除。
    但是，延迟这个时间在分布式和高并发场景下，其实是很难评估的。
    - 先更新数据库，后删除缓存
    推荐使用该方案，但是对于删除缓存失败的情况需要增加消息队列来异步重试删除缓存
    如果追求强一致性，可添加分布式读写锁
    ```

58. Redis分布式锁实现原理

   ```
    1.上锁使用Redis的SET NX PX命令，占一个 “锁key”，谁占住谁执行，占不住就循环等待,
      并且必须设置过期时间，防止服务挂了造成死锁
        
    2.释放锁不能直接DEL,必须先判断锁是不是自己的，再删锁，防止误删了别人的锁，
      并且必须使用lua脚本来保证原子性
     
    3.在实际项目中可使用第三方工具Redisson，该工具提供了可重入的分布式锁。
   ```
